# Berlin 랩타임 개선 실험 계획

기준은 2026-11-24의 최종 TLN 우선 v1.5다. 첫 목표는 같은 24배치에서 180초 무정지·무충돌과 직접 채택률을 유지하고, 그다음 독립 배치와 ROS에서 반복 가능한 랩타임 단축을 확인하는 것이다. 13~14초 평균과 12초대 단일 기록은 별도의 장기 목표로 둔다.

## 출발점

| 지표 | 기존 탐색형 v1.5 | 직전 TLN 우선 | 현재 TLN 우선 |
|---|---:|---:|---:|
| 180초 오프라인 완주 | 24/24 | 24/24 | 24/24 |
| 배치별 최고 랩 평균 | 16.8550초 | 16.9555초 | 16.8502초 |
| Avoid TLN 직접 채택 | 0% | 87.94% | 88.14% |
| 전체 최소 장애물 간격 | 10.97cm | 11.17cm | 12.37cm |

현재 버전은 기존 탐색형보다 1개 장애물에서 평균 0.075초 빨랐지만 3개에서 0.021초, 5개에서 0.040초 느렸다. 장애물 5개인 confirm-5-03의 ROS 180초 최고 랩도 직전 TLN 우선에서 18.629초, 현재 버전에서 19.112초였다. 한 번씩의 ROS 기록에는 실행 간 편차가 섞여 있다. 앞서 측정한 Race 시간 증가 0.287초 중 약 0.279초는 모드 전환 위치 차이다. 시간 손익은 같은 물리 구간에서 판정한다.

이전 3.75m/s ROS 기록의 장애물 5개 배치에서는 18.398초 중 15.15초를 Avoid로 주행했다. 현재 24배치에서도 장애물 밀도별로 손실 구간을 먼저 구분한다. 이전 5.25m/s 개발 후보는 한 배치에서 13.387초를 기록했지만 다른 배치에서는 첫 랩 뒤 제동 보호 정지가 발생했다. 이 경우를 속도 후보의 회귀 시험에 포함한다. ## 1. 먼저 줄일 수 있는 시간을 측정한다

- [ ] 기존 24배치와 confirm-5-03의 오프라인·ROS 로그를 재사용한다. 스카우트 랩을 분리하고, 같은 배치·랩·장애물 통과 순서에서 거리 기준으로 정렬한다. 복귀 비교는 두 버전 모두 Race로 돌아온 지점을 시작으로 이후 1m와 3m를 측정한다. 3m 안에서 다음 회피가 시작된 경우는 연속 장애물 구간으로 따로 비교한다.
- [ ] 구간별 실제 통과 시간, 실제·명령 속도, 제동 개입, 횡·방향 오차, 통과 거리, 장애물·벽 여유를 기록한다. 최저속 지점이 옮겨갔는지, 재가속 명령 자체가 늦었는지, 명령은 빨랐지만 실제 속도가 따라오지 못했는지를 판별한다. 제동, 회피, 복귀, 다음 직선에 걸친 시간 차의 합을 전체 랩 차와 대조한다.
- [ ] Race 상한에 실제로 도달한 구간만 골라 속도 상향의 이득을 낙관적으로 계산한다. 같은 구간 길이 d에서 현재 상한 v₀와 후보 상한 v₁의 차이는 d × (1/v₀ − 1/v₁)초다. 가감속 거리를 제외한 상한 추정치다. 직선에서 얻을 수 있는 시간이 작으면 코너와 회피 출구부터 수정한다.
- [ ] 기존 로그로 구분하기 어려운 원인만 새로 계측한다. 시뮬레이터 정답은 평가기에만 둔다. 컨트롤러는 LiDAR, 추정 자세, 정적 Berlin 지도와 해당 주행에서 만든 계획만 사용한다.

## 2. 속도 상한 4.5m/s에서 가장 큰 손실 하나를 고친다

- [ ] **회피 출구의 궤적이 원인이면** 차체와 앞바퀴가 같은 위치에서 어떤 방향을 향하는지 비교한다. 복귀 후 횡오차가 다시 커지는 경우, 입력 조향 지연을 반영한 예측 자세로 라인 수렴 여부를 확인한다. 연속 장애물 사이에서는 한 번 복귀했다 즉시 다시 감속하는 손실도 함께 평가한다.
- [ ] **속도 명령이 원인이면** 제동이 풀리는 조건, 랩 계획·곡률·시야 상한, 다음 장애물까지의 제동 거리를 개별 기록한다. 병목으로 확인된 제약 하나만 수정하고, 다음 감속 지점까지의 제동 가능 거리와 현재 조향으로 안전한지 검증한다. 초기 단계에서는 상·하한 설정을 변경하지 않는다.
- [ ] **구간 선택이나 명령을 바꿔도 같은 상태에서 모델 조향이 반복해서 벗어나면** Race와 Avoid 원시 출력, 교사 조향, 실제 전송 조향을 같은 저장 상태에서 비교한다. 이 경우에만 해당 상태·속도대의 교사 데이터 보강 및 재학습을 별도 후보로 올린다. 지연·경로·가중치 변경 효과가 섞이지 않게 한 번에 하나씩 바꾼다.
- [ ] 후보마다 실패 직전과 느린 출구의 저장 상태부터 재생하고, 다음 장애물과 제동 지점까지 추적한다. 이득을 보인 후보만 첫 랩부터 초기화하는 180초 시험으로 넘긴다. 시드 번호나 절대 위치로 동작을 바꾸지 않는다.

## 3. 같은 24배치와 ROS에서 후보를 가른다

- [ ] 장애물 1·3·5개 각 8배치, 180초, 같은 배치·노이즈로 기준과 후보를 비교한다. 배치마다 첫 랩에서 계획을 새로 만든다. 전 배치 무정지·무충돌, 첫 랩 완주, 직접 채택률 최소 87.94%를 요구하고 현재치 88.14%와의 차이도 적는다. Avoid 하한 2.7m/s, 센서 보호 150ms를 유지한다.
- [ ] 배치별 최고 랩 평균의 첫 실용 목표를 **16.65초 이하**로 제안한다. 16.8502초에서 약 0.20초 단축하는 공학적 목표다. 전체 평균, 장애물 개수별 평균, 중앙값, 개선 배치 수, 연속 랩, 최소 여유, 제어시간 p99·최대·25ms 초과 횟수를 함께 본다. 기존 탐색형과 현재 TLN 우선을 모두 대조군으로 둔다.
- [ ] ROS는 confirm-5-03과 장애물 1·3개 대표 배치에서 시작한다. 단계별 후보·기준 실행 순서를 교차하고 같은 노이즈 시드로 짝지어 각 3회 이상 측정한다. 제어 프로세스는 같은 CPU 조건으로 실행한다. 마감 초과 시 경과 시간과 스레드 CPU·실행 대기를 구분한다. ROS에서 정지·충돌이나 반복적인 기록 악화가 나타나면 채택을 보류한다.
- [ ] 개발 결과가 재현되면 설정을 동결하고 새 무작위 300배치(1·3·5개 각 100개)를 평가한다. ROS 반복용 30배치는 결과를 보기 전에 뽑는다. 과거 튜닝에 쓴 300배치와 새 검증 배치를 구분한다. 180초 원기록과 대회 방식인 180초 또는 10랩 중 먼저 도달한 시점의 최고 랩·연속 랩을 함께 낸다.

## 4. 상한은 한 단계씩 올린다

- [ ] 4.5m/s에서 손실 구간과 안전 여유를 확인한 뒤 4.75, 5.0m/s 순으로 별도 후보를 시험한다. 하한을 같이 올리지 않는다. 실제로 상한을 쓰는 시간, 다음 코너의 제동 손실, ROS 기록, 완주율을 확인한 후 다음 단계로 간다. 10m/s는 설계 한계다.
- [ ] 현재 평균에서 14초까지는 2.85초, 13초까지는 3.85초 단축이 필요하다. 단계별로 같은 위치에서 회수한 시간을 누적해 이 목표를 다시 평가한다. 과거 1개 장애물 한 배치의 13.837초 기록은 비교 사례로 남긴다.
