# Berlin 장애물 1개에서 12초대 베스트랩 달성 계획

**목표**는 Berlin 정방향 장애물 1개에서 첫 제어부터 180초간 충돌·정지 없이 달리고 12.999초 이하의 베스트랩을 기록하는 것이다. 첫 개발 배치는 new-1-051이며, 배치 간 재현성과 대회용 기본 설정 채택은 별도로 검증한다.

**구현 방향**은 첫 랩의 계획이 준비된 뒤 동일한 C++ 라우터의 Race 속도 명령만 개선하는 것이다. 기존 TLN과 조향, 원본 Avoid 계획 속도 2.7–3.0m/s, 0.18초 Race 제동 예측, 센서 보호 150ms, 제어 예산 25ms를 유지한다. 장애물 수·시드·절대좌표·특정 웨이포인트로 분기하지 않는다. 시뮬레이터 정답은 채점과 사후 분석에서만 사용한다.

근거는 [12초대 가능성 실험](../../../experiments/berlin-endurance/lap12-feasibility.md)과 [180초 평가](../../../experiments/berlin-endurance/README.md)다. 구현 시 각 단계의 결과를 검토하고 다음 실험으로 넘어간다.

## 1. 0.718초를 어디서 줄일지 계측한다

- [ ] 로컬 기존 로그 `el-project/native/runs/berlin-12s-feasibility/new-1-051-4.0{,-judge}.csv`와 독립 채점의 결승선 시각을 맞춘다. 4랩째 13.717초 중 Race는 40.78m/11.317초, Avoid는 6.45m/2.400초였다. 같은 거리와 Avoid 시간을 유지하면 Race 평균을 3.60에서 3.85m/s로 올려야 한다.
- [ ] `experiments/berlin-endurance/`의 분석에서 베스트랩과 2랩 이후 중앙값(14.162초)을 같은 누적거리에서 비교한다. Race에서 목표속도 ≥3.95m/s, 추정속도 ≥3.9m/s인 시간은 베스트랩의 6.797초였다. 가속 가능 직선, 곡률 감속, 장애물 접근, Avoid 복귀로 나눠 시간·실제속도·명령속도·최소 제동 여유를 비교한다. 구간 구분은 사후 분석에만 사용한다.
- [ ] `include/el/section_router.hpp`에서 정책 요구속도, 곡률 상한, 계획 상한, 시야 상한, 최종 명령을 구분해 기록한다. 같은 4.0m/s 설정에서 계측 전후 오프라인 조향·속도·랩타임이 일치해야 한다.

## 2. 같은 진입 상태에서 빠른 명령의 실패 원인을 분리한다

- [ ] `src/eval_avoid.cpp`의 기존 checkpoint 저장·복원을 사용한다. new-1-051의 4.0m/s 성공, 4.25m/s 벽 충돌, 4.5m/s 제동 거부를 비교한다. 최종 정지 위치에서 거슬러 올라가 진입 속도·횡위치·조향이 처음 갈라지는 시점을 찾고, 공통 접두 주행에서 그 직전 상태를 저장한다.
- [ ] 같은 상태와 센서 노이즈에서 가속 시작과 다음 감속 시작을 한 요소씩 바꾼다. 장애물 진입 자세, 조향 적용 지연, 현재 명령 후 완전히 멈출 때까지의 차체 여유, 출구 통과 시간을 기록한다. 관측한 오차 범위에서 초기 방향·속도를 바꿔도 보호 거부가 없는 후보만 전 구간 평가에 올린다.

## 3. Race에서 사용할 수 있는 속도를 연속적으로 계산한다

- [ ] 첫 후보는 `include/el/section_router.hpp`에서 현재 LiDAR 시야 거리, 지연 중 이동거리와 제동거리로 허용 속도를 계산한다. 기존 직선 추가 가속은 설정한 최고 속도 전체를 허용할 때만 가속한다. 새 후보는 현재 확보한 거리에서 가능한 중간 속도를 사용한다. 전방 곡률·첫 랩 장애물 계획·제동 예측·최종 안전 검사의 상한을 모두 적용한다. 시야가 짧거나 스캔이 불확실한 경우 추가 가속을 해제한다.
- [ ] 기준은 new-1-051의 성공 설정인 Race 4.0m/s, straight_boost=false다. 실패 재생을 통과한 다음 새 후보의 최고 허용값을 4.25 → 4.50m/s로 단계적으로 시험한다. 실패한 증속 단계는 먼저 원인을 확인한다. 베스트랩과 중앙값, 연속 랩 수를 함께 비교한다. 회귀 시험에는 시야 축소, 커브 직전, 다음 장애물 접근, 늦은 스캔, 조향이 풀리지 않은 출구를 포함한다.
- [ ] 0.718초가 남는 원인이 코너 출구에 집중될 때만 두 번째 후보를 만든다. 전방 곡률과 다음 감속 목표 속도에서 역산한 제동 시작 거리를 사용해, 조향이 풀리고 차체 경로가 열린 시점에 재가속한다. `include/el/lap_plan.hpp`와 기존 곡률 상한을 공유한다. 첫 후보 단독·두 번째 단독·조합을 같은 배치로 비교해 각각의 기여를 기록한다. 원본 Avoid와 TLN 재학습은 첫 구현 범위 밖이다.

## 4. 목표 달성과 일반화를 별도로 판정한다

- [ ] 개발 순서는 실패 직전 분기 재생 → 6개 기존 배치의 오프라인 180초 → ROS new-1-051이다. 180초 통과, 접촉·정지·안전 거부 0과 베스트랩 ≤12.999초를 **같은 주행**에서 충족해야 한다.
- [ ] 첫 달성 후 코드·모델·파라미터를 고정한다. ROS에서 동일 배치에 사전 지정한 센서 노이즈 시드 3개를 적용한다. 3회 모두 안전하게 180초를 채우고 12초대를 기록할 때 해당 배치에서 목표가 반복 재현됐다고 판정한다. 2랩 이후 중앙값과 연속 랩 수도 보고한다.
- [ ] 미사용 장애물 1개 배치 30개에서 현행과 후보를 짝 비교한다. 안전 완주율과 ‘180초 안전 완주 + 12초대’ 달성률을 각각 분모 30으로 보고한다. 이후 기존 장애물 1·3·5개 300개에서 현행 3.5m/s와 비교한다. 기본 설정 채택은 기존 성공 배치의 신규 실패, 첫 랩 회귀, 신규 충돌이 없고 ROS에서 센서·제어 보호 위반이 없을 때 판단한다. 한 배치의 베스트랩만으로 일반화나 채택을 선언하지 않는다.
