# Berlin 정방향에서 남은 다섯 배치의 통로 탐색 실패

같은 장애물 좌표 및 시작 조건의 100개 3랩 평가에서 기존 95개, 수정 후 100개가 통과했다. 기존 완주 배치의 새 실패는 0개, 전체 충돌은 0건이다. 2·3랩의 원본 Avoid 목표 속도 하한은 2.7 m/s, ROS 센서 보호 기준은 150 ms다.

## 실패 프레임에서 확인한 원인

95개 통과 빌드로 최초 거부 및 그전 랩 기록이 다섯 건 모두 재현되는지 확인했다. 다섯 차량은 같은 연속 코너에서 장애물과 벽 사이로 진입했다. 격자의 최초 단절 단계에 빈 후보는 남았으나, 직전 단계에서 이어지는 후보는 모두 사라졌다. 기본 탐색은 기준선 방향에 맞춘 직사각형으로 각 행의 차체 점유를 검사한다. 차가 비스듬히 진입해서 돌아 나갈 때는 차체의 모서리가 차지하는 위치가 이 가정과 달랐다.

|---|---:|---:|---:|---:|---:|---|
| 1846076 | 2 | 67.35 | 5 | 3 | 19 | 26.34 / 17.62 / 17.57 |
| 2238863 | 1 | 19.04 | 3 | 4 | 23 | 30.32 / 18.62 / 18.58 |
| 8181110 | 1 | 21.48 | 2 | 1 | 12 | 28.67 / 18.51 / 18.47 |
| 9699447 | 1 | 20.96 | 3 | 1 | 11 | 28.80 / 17.38 / 17.37 |
| 9701112 | 1 | 21.38 | 6 | 1 | 23 | 28.82 / 18.36 / 18.33 |

실패 자세 반경 1.5 m의 센서 점유 셀을 지도 및 시뮬레이터의 실제 장애물 도형과 대조했다. 중복을 시드별로 세어 총 121개 중 장애물에서 6 cm 이상이고 지도 벽에서도 8 cm 넘게 떨어진 셀은 0개였다. 같은 점유 격자에서 곡선 접선 방향으로 차체를 검사하면 다섯 상태 모두 6.2 m 계획 구간에 걸친 기하 후보가 남았다. 실제 장애물 좌표는 이 사후 분석과 평가에만 썼다.

1846076은 2랩에서 연속 장애물 사이를 양쪽으로 가로지르던 중 끊겼다. 2238863은 코너 진입 시 선호 통로가 좌우로 반복 전환됐다. 8181110, 9699447, 9701112는 안쪽 통로를 목표로 두었지만 차량이 바깥쪽으로 진입했다. 9699447은 장애물에 이르기 전에 0.5초 조향 예측이 끝나는 구간에서 짧은 경로와 실제로 필요한 선회가 달랐다.

## C++ 변경과 검증

기존 격자 탐색이 모두 끊기면 측정 자세에서 직전 경로의 앞쪽 구간으로 부드럽게 합류하는 곡선을 생성한다. 곡선의 실제 방향에서 기존 6.5 cm 탐색 여유로 끝까지 차체 점유를 검사한다. 급한 안쪽 코너에서는 약 1 m 앞 경로의 방향을 조향 후보에 반영한다. 급커브에서 회피 경로가 기준선에서 벗어나면 차량 속도에 따라 조향 명령 예측을 0.5~1.4초로 조절한다. 조향 명령은 기존의 지연·차체·Gym 및 제동 검사를 통과해야 한다.

짧은 예측을 유지한 중간 빌드는 오프라인 99/100, ROS 8/10이었다. 9699447의 ROS 두 주행은 1랩 21.09 m 및 21.19 m에서 멈췄다. 예측을 늘린 다음 빌드는 오프라인 100/100, ROS 9/10이었다. 8181110의 두 번째 랩 89.27 m에서 통로 탐색 18.92 ms, 전체 계산 25.76 ms로 25 ms 기한을 넘겨 보호 정지했다. 최종 빌드는 매 차체 표본마다 최신 스캔의 정렬된 점유 셀 목록을 이진 탐색하던 연산을 셀별 마스크 조회로 바꿨다. 스캔 교체·초기화·체크포인트 복원 시 같은 점유 셀을 재구성한다. 기존 제어 기한과 센서 보호 설정을 유지했다. 최종 검증에는 중간 빌드의 성공 주행을 섞지 않았다.

## ROS 2 시뮬레이션

시드마다 시뮬레이터와 제어기를 새로 시작해 독립적으로 두 번 주행했다. 각 주행이 Berlin 시작점 및 빈 계획에서 출발하는지, 실제로 게시한 세 장애물 자세가 원래 배치와 일치하는지 확인했다. 원본 Avoid의 속도 하한은 계획을 적용하는 2·3랩의 목표 명령에 적용된다. 통과 조건은 첫 랩 탐색 후 계획 생성, 2·3랩 계획 감속 작동, 주행 중 정지·충돌·센서 타임아웃 없이 3랩 완주다. 최종 통과는 10/10회다.

| 시드 | 1회차 1·2·3랩 (초) | 2회차 1·2·3랩 (초) |
|---|---|---|
| 1846076 | 26.32 / 17.67 / 17.63 | 26.27 / 17.63 / 17.62 |
| 2238863 | 30.10 / 18.58 / 18.50 | 30.02 / 18.60 / 18.58 |
| 8181110 | 27.58 / 18.17 / 18.05 | 27.73 / 18.12 / 18.08 |
| 9699447 | 28.45 / 17.37 / 17.33 | 28.65 / 17.40 / 17.32 |
| 9701112 | 28.93 / 18.37 / 18.33 | 28.50 / 18.40 / 18.32 |

점유 셀 조회 최적화 전후의 100개 오프라인 결과 레코드가 전부 일치했다. 9699447의 저장 상태를 복원한 이후 제어 주기 1,956개도 원래 주행과 일치했다.

ROS 주행 중 최대 제어 시간은 17.10 ms, 최대 스캔 나이는 24.59 ms였다. 같은 배치 100개에 대한 재검증이며 신규 시드에 대한 독립 검증은 이번 실험 범위에 포함하지 않았다.

## 재현

el-native-dev의 /workspace에서 ROS Humble 및 기존 race_stack 환경을 불러온 후 사용한다. 기존 결과를 보존하려면 새 출력 이름을 사용한다.

```bash
source /opt/ros/humble/setup.bash
source /home/misys/forza_ws/race_stack/install/setup.bash
export PYTHONPATH="/home/misys/forza_ws/race_stack/base_system/f110_simulator/f1tenth_gym/gym:${PYTHONPATH:-}"
export OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1
cmake --build /build --target el_eval_avoid el_controller el_tests el_replay_corridor -j2
ctest --test-dir /build --output-on-failure
cd /workspace/runs/berlin-remaining-five
python3 evaluate.py repeat-100 /build/el_eval_avoid all
python3 ros.py repeat-ros
python3 audit.py repeat-100 repeat-ros
```
