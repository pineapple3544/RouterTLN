# 첫 랩 기록으로 만드는 Race 속도 계획

Berlin 정방향에서 첫 성공 랩의 장애물 회피 구간과 횡방향 추종 오차를 기록한다. 다음 랩의 Race 속도는 전체 트랙을 대상으로 한 번 계산한다. 같은 장애물 배치 안에서는 노면과 장애물이 유지된다고 가정한다. run을 시작하면 계획과 기억을 비운다. 제어기에는 시드, 장애물 개수·정답 위치, 실제 자차 위치 또는 Berlin 특정 구간의 상수를 전달하지 않는다.

## 속도 계획과 실제 명령

1. 각 웨이포인트에서 지도 곡률과 첫 랩 추종 오차로 횡가속 허용 범위를 구한다. 관측한 회피 구간에는 Avoid 진입 속도를 부여한다. 랩의 출발점과 지도의 첫 웨이포인트가 다르거나 회피 구간이 결승선을 넘는 경우도 포함한다.
2. 가장 낮은 목표 속도부터 역방향으로 제동 가능 속도를 전파하고, 순방향으로 가속 가능 속도를 전파한다. 속도 제곱과 실제 웨이포인트 간 거리를 사용한다. 로컬 시뮬레이터의 계획 가속은 3.0m/s², 감속은 2.6m/s²다.
3. 주행 중에는 현재 위치에서 0.22초의 응답 지연 동안 이동할 구간까지 연속 보간한 속도 중 최솟값을 사용한다. 실제 시야, 조향·방향 오차, 장애물 접근 계획, 기존 제동 검사로 명령을 더 낮출 수 있다. ROS CSV의 `race_plan_cap`과 오프라인 tick의 `speed_limits.race_plan`이 계획값이다. 값이 -1이면 해당 주기에 계획을 적용하지 않은 것이다.
4. 150ms 센서 타임아웃, 25ms 제어 예산, 기존 0.18초 제동 예측, 추가 0.24초 출구 검사와 원본 Avoid 2.7–3.0m/s 설정을 사용했다. 계획은 기본값이 꺼진 시뮬레이터 실험 옵션이다.

## 현재 주행선의 시간 여유

이전 `ros-production-repeat`의 실제 베스트 13.706초 랩 궤적을 25ms 간격으로 재표본화했다. 물리 로그 위치로 구한 접선 방향과 속도에 9샘플 2차 Savitzky–Golay 미분을 적용했다. Race의 양의 가속, 감속 크기, 횡가속 크기의 90·95백분위 수를 각각 상한으로 취하고, 곡률과 양방향 속도 제약으로 시간을 다시 적분했다. Avoid 시간은 실제 기록을 유지했다. Race 상한 5.25m/s에서 각각 12.365초, 12.058초였다. 이는 성공 궤적의 기하학적 여지를 추정한 수치다. 횡·종방향 타이어 힘의 결합, 제어 지연, 센서 오차와 안전 거부는 시간 추정에 포함되지 않는다. 물리 로그는 이 사후 분석과 독립 채점에만 사용했다.

기존 평가의 같은 6개 배치, 같은 센서 노이즈, 같은 모델을 사용했다. 각 run에서 새로 정찰했다. 180초 무정지·무충돌 통과 수는 상한 4.0 / 4.25 / 4.5 / 4.75 / 5.0 / 5.25m/s에서 각각 6 / 6 / 5 / 5 / 3 / 4였다. 동일한 4.25m/s에서 이전 시야·출구 방식은 1/6, 새 계획은 6/6이었다. 아래 비교에서 이전 방식은 동일 상한 5.25m/s의 시야·출구 제어다. 숫자는 180초를 통과한 run의 베스트랩(초)이다.

## 같은 상태에서 조향 비교

평가기의 체크포인트에서 같은 센서 상태, 모델, 조향 액추에이터, 종방향 계획과 안전 검사를 사용했다. 분기는 75제어주기(1.875초)다. 교사 분기는 기존 SVG-MPPI가 산출한 조향만 사용한다. 교사가 보는 지도와 점유·자차 추정치도 센서 기반이다. 두 조향이 다른 궤적을 만들면 피드백 속도 명령도 달라질 수 있다. 학습용 데이터 생성과 가중치 업데이트는 수행하지 않았다.

- 둘째 랩 첫 커브의 같은 상태에서 방향·속도 오차 (0, 0), (+0.02rad, +0.1m/s), (−0.02rad, −0.1m/s)를 주었다. 5.25m/s 계획에서 원본 Race TLN과 교사 모두 세 분기를 통과했다. 오차 없는 분기의 정적 벽까지 최소 거리는 추정 위치 기준 각각 약 0.14m와 0.16m였다. 지도 해상도는 0.04m여서 0.02m 차이로 조향 우열을 판단하기 어렵다.
- 기존에 새로 실패했던 장애물 3개 배치 두 곳의 진입 상태에서도 두 조향이 기본 분기를 통과했다. TLN은 두 배치의 ±오차 분기까지 모두 통과했다.
- 새 계획에서 나중에 발생한 누적 260.37m의 제동 거부도 재현했다. 약 2m 앞의 같은 상태에서 TLN 기본 분기는 멈췄고 ±오차 분기는 통과했다. 교사는 기본 상태의 첫 제어부터 유효한 계획을 반환하지 못했다. 이 구간에서 교사가 더 안전한 조향을 제시했다는 근거는 없다.

## ROS 180초

개발 배치 `new-1-051`의 독립 물리 채점이다. 첫 세 설정을 시험할 때 일부 실험은 다른 코어를 사용한 평가와 시간상 겹쳤다. 4.25m/s 본시험 두 번은 ROS 주행을 순차 실행했다. 단독 본시험 첫 run에는 별도 CPU 코어에서 짧은 오프라인 회귀 검증이 있었다.

4.0·4.75m/s의 보호 정지는 Avoid 진입 후 제어가 각각 25.81ms와 25.50ms 소요된 주기에 발생했다. 두 경우 모두 시간 초과를 실패로 집계했다. 5.25m/s는 물리 충돌 전에 `braking_footprint`가 발생했다. 목표는 같은 주행에서 180초 안전과 베스트랩 12.999초 이하를 함께 충족하는 것이다.

## 재현 및 가중치

이전 [실험 실행법](lap12-implementation.md)의 동일한 환경에서 `EL_RACE_LAP_SPEED=true`, `EL_RACE_SIGHT_SPEED=false`, `EL_RACE_EXIT_SPEED=false`, `EL_SPEED_CAP=4.25`를 설정한다. 모든 배치에서 같은 매개변수를 사용한다. 오프라인 평가 입력은 [6개 배치 JSON](scout-speed-cases.json)이다. 최신 빌드에서 `/build/el_eval_avoid models/avoid-corridor-v2.pt runs/scout-speed.jsonl experiments/berlin-endurance/scout-speed-cases.json models/race-berlin-wsp.pt`로 재생할 수 있다. 분기 비교는 복원 입력의 `checkpoint.race_branch.race_lap_speed=true`, `checkpoint.horizon_ticks=75`를 사용하고, 교사 쪽만 `checkpoint.compare_teacher_steering=true`로 지정한다. 소스·모델·시나리오가 식별된 체크포인트가 필요하다. 실험 원본은 로컬 `el-project/native/runs/berlin-scout-speed-plan/`에 있다.

향후 학습 후보는 진입 오차를 준 상태에서 원본 Race TLN만 실패하고 교사가 안전한 출구까지 통과하는 사례를 선별해 기존 학습 데이터와 섞는 방법이다. 교사도 실패하거나 유효한 조향을 만들지 못한 상태는 모방학습 정답에서 제외한다. 학습 여부는 배치 단위로 분리한 검증 세트에서 동일 속도 계획의 벽 여유, 출구 속도, 180초 완주가 개선되는지를 기준으로 정한다.

새 옵션을 끈 기준 주행에서는 변경 전과 7,200주기의 명령·상태·모드·시각이 모두 일치했다. 이전 빌드의 체크포인트도 복원해 130주기를 통과했다. CTest 13개 및 채점기 테스트 6개를 통과했다.
