# Berlin 정방향 LiDAR 위치 추정 실패 수정

Race 상한 3.5 m/s·제동 예측 0.18초에서 원본 Avoid와 WSP Race를 고정했다. 첫 랩은 배치마다 새 계획을 만든다. 원본 Avoid 계획 랩 속도 범위는 2.7–3.0 m/s이고, 센서 보호 기준은 150 ms다. 위치 추정 입력은 현재 LiDAR, 정적 지도, 이전 제어 명령이다.

CTest 13개가 모두 통과했다. 네 배치를 묶은 회귀 검사는 수정 전 0/4, 수정 후 4/4였다. 복구가 적용된 프레임 직후의 체크포인트를 저장·복원했을 때 이후 제어 271주기가 연속 주행 기록과 일치했다.

## 재현된 원인과 구현

기존 300개 중 3.5 m/s에서 새로 실패했던 두 배치는 셋째 랩에 각각 125.65 m와 126.86 m를 주행한 시점에 위치 추정을 중단했다. 같은 주행을 재생하니 둘 모두 유효 빔 181개를 받았고 스캔 간격은 20 ms였다. 통상 스캔 정합은 동작 예측 위치에서 각각 6.6 cm와 6.4 cm 뒤쪽으로 움직여 지도 잔차를 줄였다. 연속 두 포즈로 계산한 전후 속도는 −0.73, −0.70 m/s였고 독립 Gym 기록에서는 두 차량 모두 앞으로 2.70 m/s로 주행하고 있었다. 장애물 배치는 같고 상한이 3.0 m/s인 기준 주행에서는 두 배치 모두 완주했다.

정상적인 정합과 물리 한계 검사를 먼저 수행한다. 전진 명령·전진 예측인데 정합 결과가 후진을 가리키고 속도 오차가 3 m/s를 넘으면, 전후 이동을 동작 예측에 고정한 채 현재 스캔으로 옆방향과 회전각만 다시 정합한다. 재정합에는 기존 잔차 상한 0.065 m, 원래 최적 정합 대비 추가 손실 0.25 지도 셀 이하, 측방 이동 한 셀 이하, 기존 속도·각속도 검사를 모두 적용한다. 두 프레임 연속으로 이 복구를 허용하지 않는다. 체크포인트에는 직전 복구 여부를 저장한다. 장애물 좌표, 시드 또는 시뮬레이터의 실제 차량 포즈를 제어에 사용하지 않는다.

## 오프라인 폐루프

각 배치에서 새 계획으로 3랩 연속 완주, 물리 접촉과 보호 거부 0건, 출발 0.5 m 이후 실제 최저 속도 0.05 m/s 이상을 모두 만족할 때 통과다. 랩타임은 전후 모두 통과한 같은 배치의 2·3랩 평균이다.

| 배치 | 3랩 통과 (전 → 후) | 첫 랩 완주 | 물리 충돌 배치 | 랩타임 비교 배치 | 평균 랩타임 (초) |
|---|---:|---:|---:|---:|---:|
| 기존 300개 · 장애물 3개 | 289 → 293 / 300 | 294 → 296 | 0 → 0 | 289 | 16.874 → 16.874 |
| 신규 60개 전체 | 54 → 55 / 60 | 56 → 57 | 0 → 0 | 54 | 16.737 → 16.737 |
| 신규 · 장애물 1개 | 19 → 19 / 20 | 19 → 19 | 0 → 0 | 19 | 15.571 → 15.571 |
| 신규 · 장애물 3개 | 17 → 18 / 20 | 19 → 20 | 0 → 0 | 17 | 16.634 → 16.634 |
| 신규 · 장애물 5개 | 18 → 18 / 20 | 18 → 18 | 0 → 0 | 18 | 18.065 → 18.065 |

기존 300개는 앞선 속도 실험에서 사용한 배치다. 신규 60개는 수정 후 결과를 보기 전에 별도로 생성하고 고정했다. 장애물 1·3·5개를 각 20개 배치에 사용했다. 배치 생성 시 주행 시작점 기준 5.5–44.9 m, 장애물 사이 최소 1.5 m, 측방 오프셋 ±0.18 m에서 추첨했다. 동일한 배치와 센서 시드로 이전·수정 바이너리를 각각 실행했다.

수정 후 기존 300개에서 남은 실패는 회피 통로 탐색 실패 6개와 제동 경로 거부 1개다. 물리 충돌은 0건이다. 같은 3.5 m/s 제어를 유지해 속도 조절의 영향을 분리했다.

## ROS 확인

두 대상 배치에서 이전·수정 바이너리를 각 한 번씩, 동일한 배치와 스캔 노이즈 시드 12345로 실행했다. 독립 심판이 네 실행 모두 정지·충돌·제어기 오류 0건과 실제 3랩을 확인했다. ROS에서 기존 실패가 재현되지는 않았다. ROS 전후 비교는 회귀 확인이며, 실패 해소의 근거는 오프라인 원인 계측 및 재생이다.

## 재현

이 저장소를 `/workspace`에 마운트한 기존 ROS Humble·Gym 환경에서 실행한다. 실행 전에 ROS 환경과 프로젝트 Gym의 `PYTHONPATH`를 설정한다. 평가기는 기본적으로 `/build/el_eval_avoid`를 사용하고 `EL_EVAL_BINARY`로 바꿀 수 있다. 전후 바이너리에 같은 명령과 서로 다른 출력 이름을 사용한다. `regressions`는 대상 네 배치 중 하나라도 실패하면 비정상 종료한다.

```bash
source /opt/ros/humble/setup.bash
source /home/misys/forza_ws/race_stack/install/setup.bash
export OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1
export PYTHONPATH="/home/misys/forza_ws/race_stack/base_system/f110_simulator/f1tenth_gym/gym:${PYTHONPATH:-}"
cmake --build /build --target el_eval_avoid el_controller el_scan_localizer_test
ctest --test-dir /build --output-on-failure
EVAL_CORES=0,2,4,6 python3 experiments/berlin-localizer-recovery/verify.py regressions fixed
EVAL_CORES=0,2,4,6 python3 experiments/berlin-localizer-recovery/verify.py evaluation fixed
EVAL_CORES=0,2,4,6 python3 experiments/berlin-localizer-recovery/verify.py holdout fixed
```
